# Contributing Guide

Welcome to the SIH26 Engineering Team!

Thank you for contributing to this project. This document explains the workflow and expectations for all contributors.

---

# Our Goal

We aim to build high-quality software using professional engineering practices. Every contribution should improve the project while maintaining code quality, readability, and consistency.

---

# Before You Start

Before contributing, please read:

- Engineering Handbook
- Git Workflow
- Branching Strategy
- Coding Standards

These documents define how we work as a team.

---

# Development Workflow

Every task follows this workflow:

```
Issue
    ↓
Create Branch
    ↓
Develop
    ↓
Commit
    ↓
Push
    ↓
Pull Request
    ↓
Review
    ↓
Merge
```

---

# Creating an Issue

Before starting any work:

- Check if an issue already exists.
- If not, create a new issue.
- Clearly describe the problem or feature.
- Assign the issue if appropriate.

---

# Branch Naming

Use the following naming conventions:

```
feature/<feature-name>

bugfix/<bug-name>

hotfix/<issue-name>

experiment/<idea-name>

release/<version>
```

Examples:

```
feature/login

feature/dashboard

bugfix/api-timeout

experiment/object-detection
```

---

# Commit Messages

Follow Conventional Commits.

Examples:

```
feat: add authentication

fix: resolve login bug

docs: update README

refactor: simplify API service

test: add unit tests

ci: configure GitHub Actions
```

---

# Pull Requests

Every Pull Request should:

- Solve one problem only.
- Be linked to an issue.
- Include a clear description.
- Pass all required checks.
- Be reviewed before merging.

Do not merge your own Pull Request without approval unless it is an emergency.

---

# Coding Standards

All code should:

- Be readable.
- Be modular.
- Be tested before submission.
- Follow the project's coding standards.
- Avoid unnecessary complexity.

---

# Documentation

Whenever appropriate, update documentation along with your code.

Examples:

- README
- API Documentation
- Architecture
- Setup Instructions

---

# Reporting Bugs

When reporting a bug, include:

- Description
- Steps to reproduce
- Expected behaviour
- Actual behaviour
- Screenshots (if applicable)
- Environment details

---

# Requesting Features

Feature requests should include:

- Problem statement
- Proposed solution
- Expected impact
- Alternative approaches

---

# Code Review

Reviews should focus on:

- Correctness
- Readability
- Security
- Performance
- Maintainability

Feedback should always be respectful and constructive.

---

# Communication

If you are blocked:

- Inform the team early.
- Ask questions.
- Discuss technical decisions openly.
- Share useful resources.

---

# Professional Conduct

All contributors are expected to:

- Respect teammates.
- Be professional.
- Accept feedback positively.
- Help others when possible.
- Take ownership of assigned tasks.

---

# Thank You

Thank you for contributing to SIH26. Together, we aim to build innovative solutions and learn professional software engineering practices throughout our Smart India Hackathon journey.
